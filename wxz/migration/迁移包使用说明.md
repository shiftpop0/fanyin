- 实际操作系统：Ubuntu 22.04.5 LTS（现有镜像已经成功运行，不要求升级系统）。
- 原项目：`/home/gezhi/fanyin/tailect`。
- 原容器：`asr_instance_6006`，当前停止，保留用于回退。

## 3. 解压和准备旁路 release

### 当前生产是 R8 或早期 R9 时应用最新 R9 修正

R8 曾错误地在服务端加入双声道合并；早期 R9 又对分段识别全文执行第二次全局
ForcedAligner，生产样本会触发 `E016`。最新 R9 不重新创建 release，而是在当前
release 上应用专用增量包，撤销服务端 downmix，并让 8885 `diarize=1` 直接继承
6006 原生 `speaker_segments` 的文字、说话人和时间：

```bash
cd /home/gezhi/fanyin/fanyin-new4.1-incremental-20260831-r9
sha256sum -c SHA256SUMS

RELEASE_ROOT=/home/gezhi/fanyin/releases/new4.1-20260829 \
bash migration/apply_r9_api_parity.sh
```

应用脚本只备份并覆盖 R9 清单内文件，不停止或重启容器，也不会删除任何文件。
应用后需要在维护窗口重启本项目的 6006/8885 容器，并执行
`migration/acceptance_r9_api_parity.sh`。完整步骤见
[README_r9_api_parity.md](./README_r9_api_parity.md)。浏览器端声道合并由油猴脚本
`0.5.2` 完成；R9 服务端不得出现 R8 的 downmix 日志。

将压缩包传到 `/home/gezhi/fanyin`，然后运行：

```bash
cd /home/gezhi/fanyin
tar -xzf fanyin-new4.1-incremental-*.tar.gz
cd fanyin-new4.1-incremental-*
bash migration/prepare_release.sh
```

脚本会创建：

```text
/home/gezhi/fanyin/releases/new4.1-20260829
```

它从原项目复制源码骨架，但排除 `model/`、`log/`、`outputs/`、缓存和 `.git`；随后覆盖增量文件，并创建指向原模型目录的符号链接。原项目不被覆盖或删除。

如果 release 目录已经存在，脚本会拒绝覆盖。请将旧的失败 release 移动到保留目录后再运行，不要删除。

### 已用 r6 创建 release 时应用 r7 修复

如果 `/home/gezhi/fanyin/releases/new4.1-20260829` 已经由 r6 创建，不要重新运行
`prepare_release.sh`。在 r7 解压目录中执行：

```bash
RELEASE_ROOT=/home/gezhi/fanyin/releases/new4.1-20260829 \
bash migration/apply_r7_hotfix.sh
```

该脚本只更新 r7 修复文件，更新前的副本保留在
`wxz/hotfix_backups/`；它不停止或重启容器。

## 4. 只读预检

```bash
RELEASE_ROOT=/home/gezhi/fanyin/releases/new4.1-20260829 \
bash /home/gezhi/fanyin/releases/new4.1-20260829/wxz/migration/preflight_new4_1.sh \
  | tee /home/gezhi/fanyin/releases/new4.1-20260829/tailect/log/preflight.txt
```

必须看到：

```text
PRECHECK PASSED
```

预检会检查 `speaker-diarization-3.1` 和兼容目录。模型缺失、6006/8885 被占用、GPU0 不是 4090、镜像缺失、严格说话人配置未生效时都会拒绝进入启动步骤。

## 5. 启动 new4.1

```bash
cd /home/gezhi/fanyin/releases/new4.1-20260829
GPU_ID=0 \
MODEL_DIR=/home/gezhi/fanyin/tailect/model \
IMAGE=tailect-asr-qwen3-asr:full-diar-offline \
NGINX_IMAGE=harbor.ge.cn/ailab/base/nginx:1.30.3-otel \
bash wxz/deploy/run_v4_1_single_4090.sh start
```

该脚本不会杀死端口占用者，也不会删除容器。启动后：

- 通用 API：`http://生产机IP:6006`；
- 平台 API：`http://生产机IP:8885/v1/audiototext`。

## 6. 严格验收

默认测试 URL：

```text
http://1.2.3.4/audio.wav?filename1=xxx.sdp
```

这个地址必须实际返回 WAV 内容；`xxx.sdp` 只是业务文件名。如果该地址暂时不可访问，请通过 `TEST_AUDIO_URL` 指定一条确定包含两名说话人的 WAV URL：

```bash
TEST_AUDIO_URL='http://1.2.3.4/audio.wav?filename1=two-speakers.sdp' \
RELEASE_ROOT=/home/gezhi/fanyin/releases/new4.1-20260829 \
bash /home/gezhi/fanyin/releases/new4.1-20260829/wxz/migration/acceptance_new4_1.sh
```

验收要求：

- 6006、8885 健康检查成功；
- `diarize=0` 返回非空文本和有效、单调的 ForcedAligner 时间戳；
- `diarize=1` 返回非空文本和有效时间戳；
- 双人音频至少出现两个不同 `lid`；
- 响应中的业务文件名仍为 `.sdp`，推理侧实际使用 WAV 文件。
