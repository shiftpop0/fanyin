## 8. API 架构与合同

```text
通用调用方 ───────────────> :6006 FastAPI
平台和油猴 -> :8885 Nginx -> :6006 同一 FastAPI/同一模型进程
```

`8885` 不是第二份模型，不额外占显存。它只代理：

```text
GET  /health
POST /v1/audiototext
GET/POST /translator/*
```

主要平台请求：

```bash
curl -X POST \
  'http://127.0.0.1:8885/v1/audiototext?model=Tailect_V4.1&diarize=1&language=auto&max_chars=40' \
  -F 'file=@audio.wav;type=audio/wav'
```

平台参数：

| 参数 | 说明 |
| --- | --- |
| `model` | 必须是 `Tailect_V4.1`，兼容 `v4.1` 写法 |
| `file` | multipart 音频，或允许的完整 HTTP(S) WAV URL |
| `diarize` | `0/1`；`1` 时失败必须报错，禁止伪装成单说话人 |
| `language` | `auto/zh/en/ja/ko/yue` |
| `max_chars` | 字幕行软长度上限，默认 40 |
| `split_by_punctuation` | 默认开启 |

返回重点：

```json
{
  "code": 200,
  "language": "zh",
  "data": [
    {"lid": "1", "text": "文本。", "begin": 100, "end": 900}
  ],
  "file_name": "xxx.sdp",
  "message": "",
  "uuid": "..."
}
```

时间戳必须来自本地 `Qwen3-ForcedAligner-0.6B`。对齐失败时不能生成伪造的全零时间戳。

完整合同见 [Tailect V4.1 离线接口与部署手册](./Tailect_V4.1离线接口与部署.md)。

## 9. FIFO 与 GPU

当前服务端推理队列：

```text
并发：1
最大等待者：128
默认等待超时：600 秒
```

浏览器油猴也串行处理任务。不要在当前版本上简单增加 Uvicorn worker 数；每个进程都会重复加载模型并争抢 GPU。

未来双卡的已确认方向是两个完全独立 worker：4090 一个、5070 Ti 一个，由入口 FIFO 将下一任务分配给空闲 worker。不要使用 tensor parallel 混合两张能力和显存不同的 GPU。该方案尚未实现，也未授权在本轮生产启用。

## 12. Windows 油猴现状

当前独立脚本：

```text
spyware-translator-v4.1/spyware-translator-v4.1.user.js
版本：0.5.1
```

`0.5.1` 在 Windows 浏览器端将多声道 PCM WAV 显式合并为单声道；展开按钮中的播放器与上传模型的分片使用同一份合并后音频。服务端不承担本次业务声道合并。

不要同时启用旧项目油猴和 V4.1 油猴，否则可能重复捕获、重复推理和重复写 CSV。

生产 Windows 当前应手工设置：

```text
模型服务：http://12.33.114.138:8885
模型：Tailect_V4.1
API Key：空
本机助手：http://127.0.0.1:18885
本机输出：C:\fanyin_output
语言：auto
单行最大字数：40
```

说话人只使用 `diarize=0/1`。旧的固定 `speakerCount` 已主动删除，不应恢复；当前模型自动产生说话人并映射为连续 `lid`。

本机助手未启动时：

```text

模型端 CSV           继续
网页展示与修订       继续
CSV 另存             继续
Windows 自动落盘     不可用
打开本机文件路径     不可用
```

完整助手默认监听：

```text
http://127.0.0.1:18885
```

目标业务页面当前只匹配：


## 13. 已知问题与判断

### 13.1 独立标点模型为空

生产目录与开发机目录：

```text
/home/gezhi/fanyin/tailect/model/iic/punc_ct-transformer_zh-cn-common-vocab272727-pytorch
C:\program5\fanyin4.1\tailect\model\iic\punc_ct-transformer_zh-cn-common-vocab272727-pytorch
```

两处均已确认为空目录；生产容器内外一致，缺少 `config.yaml`、`configuration.json`、`model.pt`、`tokens.txt`。因此：

```text
punctuation_ready=false
POST /punctuation 不能完成独立标点恢复
```

Qwen3 平台 ASR、ForcedAligner、说话人分离和油猴不依赖该独立端点。旁边存在完整的 Paraformer `speech_paraformer-large-vad-punc...` 模型，但它不是当前配置的独立文本 CT-Transformer；未经明确适配与验证，不得直接替换路径。

### 13.2 PyAnnote 重叠语音增强未就绪

日志显示：

```text
[PYANNOTE] Overlap detection unavailable
[PYANNOTE] Core diarization (modelscope) works normally.
```

普通 CAM++/ModelScope 核心说话人分离已加载；大量同时讲话时缺少重叠检测增强。生产环境完全离线，不得增加在线下载依赖。

### 13.3 模型日志追加

日志文件不会因重启清空，历史错误会一直存在。不要因为全文件中出现一次 `Disabled` 就判断当前失败。

### 13.4 vLLM 离线探测噪声

启动时可能显示尝试定位 `hf-mirror.com` safetensors 的错误，但 `HF_HUB_OFFLINE=1` 会立即阻止联网，随后本地权重成功加载。当前不是在线依赖。若后续优化日志，必须保证仍然完全离线。

### 13.5 Tokenizer 警告

代码已有 `fix_mistral_regex` 兼容补丁，但 vLLM 子进程日志仍可能打印 Mistral regex 警告。当前尚无证据表明它已影响实际识别结果；也不能只凭“补丁日志已打印”断言子进程一定应用成功。

### 13.6 上传音频无自动清理

见第 11.4 节，是生产磁盘增长风险。

7. 新迁移包使用新修订号，例如 r8，不覆盖旧归档；
8. 对现有生产 release 的更新必须先备份被覆盖文件；
9. 不要重新对当前 release 运行 `prepare_release.sh`；
10. 生产变更后至少确认 `/health` 和受改动功能的状态；
11. 提交到 `new4.1` 并推送 `origin/new4.1`；
12. 在文档中更新生产状态、包 SHA256 和仍然有效的已知问题。
