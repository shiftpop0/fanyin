## 8. API 架构与合同

```text
通用调用方 ───────────────> :6006 FastAPI
平台、油猴和 Web -> :8885 Nginx -> :6006 同一 FastAPI/同一模型进程
```

`8885` 不是第二份模型，不额外占显存。Web 交付后，Nginx 在 `/` 提供静态页面，并代理：

```text
GET  /health
POST /v1/audiototext
GET/POST /translator/*
```

R9 起，两个入口成功启用说话人模式时共享同一个核心：

```text
TargetDiarization → 说话人短片段 → 批量 ASR → overall_text
                                ├─ 6006 保持原生 JSON
                                └─ 8885 原生片段时间 + v1 字幕合同
```

Nginx 只转发 `/v1/audiototext` 原 URI，不会把它改写为 `/asr`。两个端口进入同一
FastAPI 进程并不等于自动执行同一路由；R9 是通过共享 Python 方法消除核心算法差异。

主要平台请求：

```bash
curl -X POST \
  'http://127.0.0.1:8885/v1/audiototext?model=Tailect_V4.1&diarize=1' \
  -F 'file=@audio.wav;type=audio/wav'
```

平台参数：

| 参数 | 说明 |
| --- | --- |
| `model` | 必须是 `Tailect_V4.1`，兼容 `v4.1` 写法 |
| `file` | multipart 音频，或允许的完整 HTTP(S) WAV URL |
| `diarize` | `0/1`；`1` 时失败必须报错，禁止伪装成单说话人 |
| `language` | 兼容接收但完全忽略，不参与识别或对齐 |
| `split_by_punctuation` | 仅 `diarize=0` 生效；默认开启 |

2026-08-31 合同校正：已从服务端处理链、后台 Web 和油猴脚本中移除每行字符数参数；
旧客户端继续发送 `max_chars` 时返回业务错误 `E017`，避免静默忽略。请求中的
`language` 保留兼容入口，但值不再传入适配器；识别语言以新模型检测结果为准。
`split_by_punctuation` 也是扩展层的字幕整形开关，并非原生 `/asr` 参数，本次按用户
限定范围暂时保留，Web 与油猴脚本均不发送它。

返回重点：

```json
{
  "code": 200,
  "language": "zh",
  "data": [
    {"lid": "1", "text": "文本。", "begin": 100, "end": 900}
  ],
  "file_name": "xxx.sdp",
  "message": "",
  "uuid": "..."
}
```

`diarize=0` 使用本地 `Qwen3-ForcedAligner-0.6B`；`diarize=1` 直接继承 6006 原生
`speaker_segments` 的真实时间。生产样本曾触发全局对齐 `E016`，因此禁止恢复
“分段 ASR 拼接全文后再全局对齐”的旧做法，也不能生成伪造的全零时间戳。

完整合同见 [Tailect V4.1 离线接口与部署手册](./Tailect_V4.1离线接口与部署.md)。

## 9. FIFO 与 GPU

当前服务端推理队列：

```text
并发：1
最大等待者：128
默认等待超时：600 秒
```

浏览器油猴也串行处理任务。不要在当前版本上简单增加 Uvicorn worker 数；每个进程都会重复加载模型并争抢 GPU。

未来双卡的已确认方向是两个完全独立 worker：4090 一个、5070 Ti 一个，由入口 FIFO 将下一任务分配给空闲 worker。不要使用 tensor parallel 混合两张能力和显存不同的 GPU。该方案尚未实现，也未授权在本轮生产启用。

## 12. Windows 油猴现状

当前独立脚本：

```text
spyware-translator-v4.1/spyware-translator-v4.1.user.js
版本：0.5.3
```

`0.5.3` 在 Windows 浏览器端将多声道 PCM WAV 显式合并为单声道；展开按钮中的播放器与上传模型的分片使用同一份合并后音频，并停止发送 `language` 和每行字符数参数。它还兼容业务 WAV 把双声道 PCM16 的 `blockAlign` 错写成单声道值 `2` 的情况，按 `channels × bits/8` 重算帧宽并校验数据完整性。服务端不承担本次业务声道合并。

不要同时启用旧项目油猴和 V4.1 油猴，否则可能重复捕获、重复推理和重复写 CSV。

生产 Windows 当前应手工设置：

```text
模型服务：http://12.33.114.138:8885
模型：Tailect_V4.1
API Key：空
本机助手：http://127.0.0.1:18885
本机输出：C:\fanyin_output
```

说话人只使用 `diarize=0/1`。旧的固定 `speakerCount` 已主动删除，不应恢复；当前模型自动产生说话人并映射为连续 `lid`。

本机助手未启动时：

```text

打开本机文件路径     不可用
```

完整助手默认监听：


### 15.1 后台 Web 交付

源码：`tailect/web/`。生产静态文件：`tailect/web/dist/`。`dist/` 是构建产物并被
Git 忽略，单纯拉取源码后不会存在。生产机离线且没有 Node.js 时，必须在同源码构建机
运行 `pnpm install --frozen-lockfile && pnpm build`，再随新的离线发布包带入完整 `dist/`。

新启动脚本在 `start` 时检查 `dist/index.html`，但 `status` 和 `stop` 不受该检查影响。
旧 `tailect-v41-platform` 容器没有 `/usr/share/nginx/html` 挂载，Docker 不能向已有
容器追加 mount；脚本会拒绝继续，不会删除旧容器。按专项文档先停止并改名保留旧容器，
再创建带只读 Web 挂载的新平台容器。

## 17. 维护与发布规则

1. 从 `new4.1` 最新提交开始；

10. 生产变更后至少确认 `/health` 和受改动功能的状态；
