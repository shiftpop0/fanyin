## 1. 结论

本次在 NVIDIA GeForce RTX 5090（32,607 MiB）上使用真实生产镜像、现有模型和真实
8 kHz 普通话音频完成验收。`mode=2` 已达到本轮目标：

1. 使用独立 FunASR FSMN VAD 切片，不经 TargetDiarization 请求调用链；
2. 返回有时间戳、无说话人字段的完整分段转译结果；
3. 问题单四个 2～5 分钟样本不再出现旧 `/asr_raw` 的 8～22 字静默截断；
4. 四个问题样本全部覆盖至音频尾部 0.02 秒以内；
5. 1、10、20、30 分钟样本全部完成，最长样本为 159/159 个片段；
6. 纯静音、8 kHz、16 kHz、单声道、双声道和中间长静音均通过；
7. 故意使说话人模块初始化失败后，`mode=2` 仍可独立成功；
8. 参数互斥、未知 mode、mode 1 兼容、模型哈希和原服务恢复均通过。

本轮没有修复 `/asr_raw` 或旧 `diarization=false`。旧路径在同一轮复测中仍稳定复现
静默截断，这反向证明本次改善来自新流程，而不是模型文件或测试材料变化。

- mode 2 与 mode 1 的字符序列相似度为 0.8925～0.9206；
- mode 2 与 mode 1 的文字长度比例为 87.1%～100.4%。

## 6. 真正跳过说话人推理

正常实例的日志顺序为：

```text
[VAD] Independent detection completed
[SEG-ASR] ... mode=vad_segment_asr
[SEG-ASR][BATCH] ...
[MODE2] ...
POST /asr?mode=2 200
```

问题单四个 mode 2 请求完成以后，日志才在第一个 mode 1 请求出现
`[DIAR] Audio duration`。这说明 mode 2 请求期没有进入说话人推理。

此外，第二个故障注入实例使用只读空目录遮蔽 TargetDiarization 项目。健康检查结果：

```json
{
  "vad_ready": true,
  "diarization_ready": false,
  "diarization_error": "Failed to import TargetDiarization class"
}
```

在该状态下，`POST /asr?mode=2` 仍返回：

```json
{
  "mode": 2,
  "segmentation_status": "ok",
  "segment_count": 4,
  "completed_segment_count": 4
}
```

全文为 33 字，片段无 `speaker` 字段。这是 mode 2 不依赖说话人模型的真实运行时证据。

## 9. 已知观察项

问题音频是普通话，但片段级 `detected_languages` 仍可能出现 `Tiantai`、`Taizhou`、
`Linhai`、`Sanmen` 等标签。旧 `/asr_raw` 同样稳定返回 `Tiantai`。本次用户已经明确
模型和生成参数不属于改动范围，因此没有更改语言检测或模型控制 token。该现象不影响
本轮“独立 VAD 分段、避免全文静默截断”的验收结论，但建议未来单独建立语言标签语义和
准确率任务。
