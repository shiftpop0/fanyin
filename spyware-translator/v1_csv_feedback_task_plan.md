# spyware-translator v1 API、音频合并、CSV 缓存与反馈改造计划

## 1. 背景与目标

本次改造目标是把 `spyware-translator.user.js` 从“捕获单段音频并调用 Gradio WebUI 私有接口”的实验形态，升级为面向实际侦控语音场景的可持续使用工具：

- 全面使用本地模型 v1 API：`POST /v1/audiototext?model=Taizhou`。
- 支持网页音频切片自动合并，按最长 10 分钟为一个识别单元。
- 支持普通语音列表界面、VX 语音界面，以及后续相似语音界面的通用捕获、识别、缓存、查看和反馈。
- 识别结果自动保存为 CSV，用于避免重复识别、便于查看和回溯。
- 结果同时尽量保存在模型端和脚本运行端，适配“运行 userscript 的电脑”和“运行模型服务的电脑”不是同一台机器的场景。
- 浮窗由“结果列表”调整为“控制台”，行内或语音项内提供展开、手动识别/重新识别、音频播放、CSV 查看、打开文件路径、修正反馈等操作。
- 在普通列表的“序号”字段右侧新增一个“识别内容”字段，直接从脚本端本地 CSV 读取带时间戳的转写内容。
- 反馈内容只需落盘到当前项目或本地输出目录，不需要转发业务系统。

## 2. 关键约束

### 2.1 两台电脑场景

实际部署可能是：

- A 电脑：打开 spyware 页面并运行 userscript。
- B 电脑：运行 Tailect ASR v1 API 服务。

因此，保存策略必须拆成两个层面：

- 模型端保存：B 电脑收到 v1 API 请求后，把 CSV 和反馈落盘到 `C:\fanyin_output\{client_ip}`。其中 `{client_ip}` 优先使用 HTTP 请求来源 IP，也允许前端显式传入 `client_ip` 作为辅助字段。
- 脚本端保存：A 电脑上的浏览器脚本不能直接静默写入 `C:\fanyin_output\` 这类任意本地目录。本次确认允许部署脚本端本地助手服务，因此把本地助手作为默认实现；助手不可用时 UI 提示本机保存失败，模型端保存仍继续执行。

脚本端保存策略：

1. userscript 调用脚本端本地助手，例如 `http://127.0.0.1:18885/local/csv/save`，由助手写入 `C:\fanyin_output\`。
2. helper 不存在或不可达时，userscript 在控制台提示本机助手不可用，不生成浏览器下载文件，也不写 IndexedDB。
3. 模型端 `/translator/csv` 保存仍执行，避免本机 helper 临时异常影响识别主流程。

### 2.2 浏览器权限边界

userscript 可以抓网页音频、发 HTTP 请求、构造 CSV、触发下载，但不能稳定做到：

- 静默写入绝对路径 `C:\fanyin_output\`。
- 打开本机 CSV 文件所在目录并选中该文件。
- 枚举本机目录内已有 CSV。

这些能力需要脚本端本地助手提供。模型端只负责模型端 CSV/反馈落盘，不提供“打开目录/打开文件路径”能力。

### 2.3 冗余要求

字段缺失不得影响识别主流程。例如普通语音列表中如果缺少“对方号码”，仍必须可以：

- 捕获音频。
- 合并音频。
- 调用 v1 API。
- 保存 CSV。
- 弹窗查看结果。

缺失字段只影响标题和文件名，应使用稳定 fallback：

- 空字段写作 `未知案件`、`未知侦控号码`、`未知对方号码`、`未知时长`、`未知开始时间`。
- 如果页面字段不足，使用 `targetfile`、音频 URL hash、捕获时间补足唯一性。

## 3. 总体架构

### 3.1 组件划分

1. `spyware-translator.user.js`
   - 捕获网页音频 URL。
   - 识别普通语音列表、VX 语音、通用音频容器的上下文。
   - 按 `targetfile`、行字段、消息字段生成 call key。
   - 下载并合并切片。
   - 调用 v1 API。
   - 调用 CSV/反馈接口。
   - 渲染控制台浮窗、行内按钮、结果弹窗、修正弹窗。

2. `tailect_asr.cli.api_v1`
   - 保持现有 `/v1/audiototext` 识别接口。
   - 增加 CSV 和反馈辅助接口。
   - 按请求来源 IP 保存模型端 CSV：`C:\fanyin_output\{client_ip}`。
   - 不提供模型端“打开目录/打开文件路径”能力，避免两台电脑场景下产生误导。

3. 脚本端本地助手服务
   - 建议放在 `spyware-translator/local_helper` 或 `spyware-translator/temp` 下。
   - 可用 Node.js 或 Python 实现。
   - 监听 `127.0.0.1`，避免暴露到局域网。
   - 写入脚本端目录：默认 `C:\fanyin_output\`，可由控制台浮窗配置。
   - 支持打开脚本端本机 CSV 文件所在目录并选中文件，UI 文案统一为“打开文件路径”。

### 3.2 推荐数据流

1. 页面加载或用户播放语音。
2. userscript 捕获 `/spyfile/audiostream.wav?targetfile=xxx.wav&index=0`。
3. userscript 建立通话任务，按普通列表/VX/通用音频提取上下文。
4. 查询模型端 CSV 状态和脚本端本地助手 CSV 状态。
5. 如果脚本端本地 CSV 已有非空内容，显示展开按钮，点击直接展示 CSV 内容；普通列表新增“识别内容”字段也从该本地 CSV 填充。
6. 如果没有 CSV，自动识别开启时加入识别队列；自动识别关闭时显示手动识别入口。
7. 识别时从 `index=0` 开始连续探测切片；默认无切片数量上限，直到连续失败达到阈值，或用户在控制台设置的切片上限被触发。
8. 按最长 10 分钟合并音频，逐段调用 v1 API。
9. 合并多个识别结果，并修正后续段落 `begin/end` 时间偏移。
10. 保存 CSV 到模型端。
11. 保存 CSV 到脚本端本地助手；如果助手不可用，则在控制台提示本机保存失败，并继续执行模型端保存。
12. 更新行内按钮状态，展开弹窗显示音频播放器和时间戳文本。
13. 更新普通列表新增“识别内容”字段，内容来源为脚本端本地 CSV。
14. 用户点击修正按钮，提交后覆盖更新当前 CSV，并追加反馈落盘。

## 4. 音频合并设计

### 4.1 分组 key

普通语音列表：

- 优先字段：案件名、侦控号码、对方号码、预估时长、通话开始时间。
- URL 字段：`targetfile`。
- 稳定 key：`normal:{caseName}:{controlNumber}:{peerNumber}:{duration}:{startedAt}:{targetfile}`。

VX 语音：

- 优先字段：联系人/发送人、消息时间、语音时长、消息方向、`targetfile`。
- 稳定 key：`vx:{user}:{time}:{duration}:{direction}:{targetfile}`。

通用音频：

- 优先字段：可见容器标题、时长、`targetfile`。
- 稳定 key：`generic:{title}:{duration}:{targetfile}`。

### 4.2 index 范围

- 从 `index=0` 开始探测。
- 只要切片下载成功，就继续尝试下一个 index。
- 默认无切片数量上限，不因普通列表预估时长或 VX 消息时长提前截断。
- 单个通话的切片探测上限可配置；如果现场需要防止异常 URL 无限探测，可在控制台配置中设置最大切片数，例如 60、120 或 300。
- 连续失败阈值在控制台配置，默认 2；失败包括 404、空音频、网络错误或无法解析的切片。
- 6 分钟音频如果实际存在 `index=0..5`，应下载并合并 6 个切片，然后在 `index=6/7` 连续失败后停止。

### 4.3 合并规则

- 每个下载到的 wav 先解析 header。
- 如果格式一致，直接拼接 PCM data，并重写 wav header。
- 如果格式不一致，尝试使用 Web Audio 解码后重采样为统一 PCM，再编码 wav。
- 每个识别单元最长 10 分钟。
- 超过 10 分钟则拆为多个合并段，逐段调用 API。
- 对第 2 段及以后返回的 `begin/end` 加上段起始偏移。

### 4.4 异常冗余

- 某个中间 index 下载失败：记录 warning，继续尝试后续 index；如果后续存在有效音频，则仍可识别。
- index=0 下载失败：任务失败，但不影响其他任务。
- wav 解析失败：尝试直接上传原始 blob；如果 API 失败，再提示音频格式问题。
- 合并后音频为空：不调用模型，写入错误状态，不生成非空 CSV。

## 5. CSV 保存设计

### 5.1 文件名

普通语音列表文件名：

```text
案件名称+侦控号码+对方号码+通话开始时间+预估时长（秒）+index=0.csv
```

示例：

```text
001专案+12312312311(xxx)+8613213213222+2026-01-01 16_30_15+34秒+index=0.csv
```

所有字段需清理 Windows 非法字符：

```text
< > : " / \ | ? * 控制字符
```

VX 文件名：

```text
VX+联系人+收发方向+消息时间+语音时长+index=0.csv
```

通用音频文件名：

```text
Audio+标题+时长+targetfile.csv
```

### 5.2 保存路径

模型端：

```text
C:\fanyin_output\{client_ip}\{csv_file_name}
```

脚本端：

```text
{configuredLocalOutputDir}\{csv_file_name}
```

控制台浮窗默认配置：

```text
C:\fanyin_output\
```

### 5.3 CSV 字段

正式字段仅使用中文表头，不再兼容旧英文 CSV：

```csv
记录键,场景,标题,案件名称,侦控号码,对方号码,预估时长（秒）,通话开始时间,音频文件,切片索引范围,分段序号,说话人,开始时间（毫秒）,结束时间（毫秒）,开始时间,结束时间,原始识别文本,修正文本,是否修正,音频流地址,识别模型,识别语言,识别任务UUID,创建时间,更新时间
```

说明：

- “原始识别文本”保存模型原始结果，“修正文本”保存人工修正结果。
- 展示时优先显示“修正文本”，为空则显示“原始识别文本”。
- “开始时间（毫秒）/结束时间（毫秒）”用于精确定位。
- “开始时间/结束时间”是可读时间，如 `00:01.280`。
- “切片索引范围”记录该 CSV 由哪些切片合并而来，如 `0-5`；列表标题和文件名仍固定显示 `index=0`。
- 已有英文表头缓存不迁移、不读取；用户重新识别后直接生成中文 CSV。

### 5.4 CSV 状态

CSV 分三态：

- 不存在：未识别，不显示展开按钮，除非用户悬浮或启用手动识别按钮。
- 存在但为空或只有表头：识别中或异常中断，显示加载状态。
- 存在且有数据行：显示展开按钮，弹窗读取 CSV 展示。

### 5.5 服务端同步状态结构

模型端需要维护独立的服务端同步状态结构，但它不再用于阻止覆盖或向脚本提示版本冲突。服务端策略改为：

- 服务端永远保存最近一次脚本端提交的 CSV。
- 脚本端触发 CSV 写入动作时，服务端直接覆盖对应模型端 CSV。
- 不通过 CSV 文件修改时间判断新旧。
- 不向 userscript 提示“版本不一致”。
- 同步状态结构只用于记录最新版本、内容 hash、写入来源和排查信息。

同步触发信号来自脚本端写 CSV 的动作事件，包括：

- 首次识别成功并生成 CSV。
- 点击“重新识别”并生成新 CSV。
- 提交打标修正并更新 CSV。
- 后续如果增加批量导入、手动保存，也按同一规则触发同步。

建议使用 Python 标准库 `sqlite3` 保存一个模型端全局同步登记库，而不是每个 IP 一个 SQLite。位置：

```text
C:\fanyin_output\.state\sync_state.sqlite
```

CSV 文件本身仍按脚本端主机 IP 分目录保存：

```text
C:\fanyin_output\{client_ip}\{csv_file_name}
```

采用全局 SQLite 的原因：

- 避免每个 IP 都生成一个 `.sqlite`，减少文件分散和运维复杂度。
- 可以在一张表里按 `client_ip`、`record_key`、`csv_filename` 查询。
- Python 标准库自带 SQLite，不增加依赖。
- 后续需要统计或排查时，比散落的 JSON 更稳定。

如果后续现场强烈要求完全可读，也可以在脚本端本地助手旁边额外写一个轻量 JSON sidecar，但主同步状态仍建议放在服务端全局 SQLite，避免 userscript 逻辑臃肿。

核心记录结构：

```text
records(
  client_ip,
  record_key,
  csv_filename,
  server_revision,
  server_version_id,
  content_hash,
  row_count,
  canonical_updated_at,
  last_write_event,
  last_client_id,
  csv_path
)
```

事件记录结构：

```text
events(
  event_id,
  client_ip,
  record_key,
  csv_filename,
  write_event,
  server_revision,
  server_version_id,
  content_hash,
  row_count,
  created_at,
  client_id,
  note
)
```

说明：

- `server_revision` 是服务端单调递增版本号，只用于记录每次服务端覆盖写入。
- `server_version_id` 是每次成功写入后生成的 UUID。
- `content_hash` 是 CSV 内容的 SHA-256，用于判断“这次写入内容是否与上次完全一致”，可用于减少重复事件或排查问题。
- `canonical_updated_at` 由服务端生成，只作为展示和排序，不作为覆盖判断依据。
- `write_event` 建议取值：`initial_transcribe`、`manual_retranscribe`、`correction_submit`、`manual_save`。
- `events` 只记录版本事件和 hash，不保存完整文本差异；它不是 feedback 历史。
- feedback 历史默认关闭时，仍保留同步登记表，因为这是服务端最新 CSV 状态的基础记录。

覆盖规则：

1. 脚本端每次提交 CSV，服务端都按 `client_ip + record_key/csv_filename` 找到对应文件并覆盖。
2. 服务端计算 `content_hash`，写入或更新 `records`。
3. 如果 hash 与上一版相同，可以只更新 `canonical_updated_at/last_write_event`，也可以记录一条轻量事件；实现时以简单稳定为先。
4. 如果 hash 不同，递增 `server_revision`，生成新的 `server_version_id`，记录事件。
5. 服务端不返回业务冲突，不要求 userscript 处理版本不一致。
6. 脚本端本地助手可只保存自己的本地 CSV，不必承担复杂同步判断；服务端是模型端 CSV 最新状态的登记者。

## 6. 服务端接口计划

### 6.1 识别接口

继续使用：

```http
POST /v1/audiototext?model=Taizhou&diarize=0
Content-Type: multipart/form-data
```

前端控制项：

- `model`: 默认 `Taizhou`。
- `diarize`: 默认 `0`，由悬浮窗开关控制。
- `language`: 默认自动识别。
- `max_chars`: 沿用服务默认或前端配置。

### 6.2 模型端 CSV 接口

新增：

```http
GET /translator/csv/status?record_key=...&filename=...
```

返回：

```json
{
  "code": 200,
  "exists": true,
  "empty": false,
  "row_count": 6,
  "path": "C:\\fanyin_output\\192.168.1.23\\xxx.csv",
  "server_revision": 3,
  "server_version_id": "9c47d1ef-7c2a-42bd-a7dd-7a75f8dba40c",
  "content_hash": "sha256:..."
}
```

新增：

```http
GET /translator/csv?record_key=...&filename=...
```

返回 CSV 文本或 JSON 包装。

新增：

```http
POST /translator/csv
Content-Type: application/json
```

用于保存或覆盖模型端 CSV，并更新服务端同步状态结构。

请求体建议包含：

```json
{
  "record_key": "...",
  "csv_filename": "...",
  "csv_text": "...",
  "write_event": "initial_transcribe",
  "content_hash": "sha256:...",
  "client_id": "...",
  "client_ip_hint": "..."
}
```

返回体建议包含：

```json
{
  "code": 200,
  "status": "saved",
  "server_revision": 4,
  "server_version_id": "5c43c82d-39e1-4eab-a06f-d5b772b8b8c5",
  "content_hash": "sha256:...",
  "csv_path": "C:\\fanyin_output\\192.168.1.23\\xxx.csv"
}
```

服务端不返回业务冲突。只要请求合法，就以脚本端本次提交的 CSV 为最新版本并覆盖保存。

### 6.3 反馈接口

新增：

```http
POST /translator/feedback
Content-Type: application/json
```

请求体包含：

```json
{
  "record_key": "...",
  "csv_filename": "...",
  "segment_no": 1,
  "begin_ms": 1280,
  "end_ms": 2240,
  "lid": "1",
  "original_text": "...",
  "corrected_text": "...",
  "context": {
    "scene": "normal",
    "title": "...",
    "case_name": "...",
    "control_number": "...",
    "peer_number": "..."
  }
}
```

落盘：

```text
C:\fanyin_output\{client_ip}\feedback.jsonl
```

同时更新对应 CSV 行的 `corrected_text/is_corrected/updated_at`，并更新服务端同步状态结构。
`feedback.jsonl` 默认不写入；只有配置开启 feedback 历史时才追加。

### 6.4 脚本端本地助手接口

建议实现：

```http
GET /local/health
GET /local/ip
GET /local/csv/status?filename=...
GET /local/csv?filename=...
POST /local/csv/save
POST /local/csv/open-path
POST /local/feedback
```

本地助手只监听 `127.0.0.1`。
`/local/csv/open-path` 使用 Windows Explorer 打开 CSV 所在目录并选中该文件；如果文件不存在，应返回明确错误，前端提示“本机 CSV 未生成”。

### 6.5 feedback 历史取舍

feedback 历史不是当前查看最新修正文的必要条件。当前可见结果以 CSV 为准，修正提交后直接覆盖对应 CSV 行即可满足“查看最新正确文本”的主目标。

保留轻量 feedback 历史能力的主要价值：

- 审计：能知道某条文本何时、由谁或由哪台机器从什么内容改成了什么内容。
- 回滚：如果误改 CSV，可从历史记录恢复上一版文本。
- 评估：后续如果需要评估模型常见错误或做微调语料筛选，历史修正比最终 CSV 更有参考价值。
- 排错：如果用户开启历史，jsonl 可以辅助判断人工修正过程；服务端 CSV 的最新状态则由服务端同步状态结构记录。

本计划将 feedback 历史设计为轻量可配置项：

- 默认关闭，因为当前主要目标是展示和保存最新转写结果，暂不强调追溯。
- 控制台或配置中可开启历史记录；开启后追加写入 `feedback.jsonl`，每行一条 JSON，不参与页面主展示。
- 即使 feedback 历史写入失败，也不回滚 CSV 覆盖结果，只在 UI 中提示“历史记录写入失败”。
- 无论 feedback 历史是否开启，服务端同步状态结构都必须更新，用于记录模型端最新 CSV 版本。

## 11. 风险与缓解

### 11.1 client IP 不准确

如果中间有代理或 NAT，模型端看到的 IP 可能不是浏览器主机真实 IP。

缓解：

- 前端调用 `/local/ip` 获取脚本端 IP，随请求传 `client_ip_hint`。
- 服务端目录优先使用可信来源 IP，也记录 hint。

### 11.2 浏览器无法脚本端落盘

缓解：

- 提供本地助手。
- 没有助手时提示本机保存失败，同时保留模型端 CSV 保存。
- 控制台提供“打开文件路径”按钮，helper 可用且 CSV 存在时打开所在目录并选中文件。

### 11.3 页面虚拟滚动导致按钮丢失

缓解：

- MutationObserver + 定时轻扫。
- 按行字段重复绑定，避免重复注入。
- 行 DOM 消失不影响任务状态。

### 11.4 切片缺失或服务端切片规则变化

缓解：

- URL 探测 + 连续失败停止。
- 预估时长只用于标题、CSV 文件名和上下文展示，不作为切片下载硬上限。
- 记录 index_range 和 warning。

### 11.5 CSV 文件名过长

缓解：

- 文件名清理后限制长度。
- 超长部分截断。
- 末尾追加短 hash 保证唯一。

### 11.6 识别耗时长

缓解：

- 队列串行处理。
- UI 显示加载状态。
- 空 CSV 作为处理中标记。
- 失败可重新识别。

- UI 只保留本机“打开文件路径”，不提供模型端打开目录或打开文件路径入口。

- 普通列表行内操作和控制台兜底操作都支持手动识别。

- 普通列表手动识别允许使用降级策略：优先静默读取行数据中的音频路径；无法读取时自动双击对应行的“案件名称”并捕获音频请求。原页面详情可能短暂显示，脚本不强制删除或隐藏未知业务 DOM。

### 13.2 控制台交互调整

- 控制台拆分为“模型服务”“本机 CSV”“识别设置”“识别控制”四部分。
- “模型服务地址”说明其用于 Tailect v1 API；“本机助手地址”说明其必须运行在 userscript 所在电脑。
- API Key 改为密码输入框，并说明仅在服务端启用 `TAILECT_API_KEY` 时填写。
- “自动开/关”改为“自动识别新音频：已开启/已关闭”。
- “说话人开/关”改为“说话人识别：已开启/已关闭”。
- 开启状态使用绿色按钮，关闭状态使用灰色按钮。
- 控制台顶部“重新识别”改为“全部重新识别”，执行前显示任务数量和覆盖 CSV 风险确认。
- “保存配置”成功后显示提示，并重新检测模型服务和本机助手。
- 模型服务、本机助手、CSV 保存、打开文件路径和手动识别失败均显示可见错误，不只写控制台日志。

### 13.3 普通列表手动识别

1. 点击“手动识别”时，脚本先读取当前 FlexGrid 行。
2. 如果页面暴露 Wijmo 控件，脚本从列标题/绑定字段中查找“语音文件存放的路径”“语音文件”“音频文件”或类似字段。
3. 如果取得 `.wav` 路径，直接构造 `/spyfile/audiostream.wav?targetfile=...&index=0`，不打开音频详情。
4. 如果取不到路径，脚本记录该行上下文并自动双击该行“案件名称”单元格。
5. 下一条 `index=0` 音频请求会绑定到该行，然后进入原有切片探测、合并和识别队列。
6. 捕获成功后恢复页面和 FlexGrid 的滚动位置；由于未知业务页面没有稳定关闭接口，不强制关闭原页面详情，并显示说明。
7. 15 秒内没有捕获到音频时显示失败提示，建议用户手动打开详情后重试。

### 13.4 FlexGrid 列布局

- 只处理 `[wj-part="chcells"]` 的可见表头行和 `[wj-part="cells"]` 的数据行。
- 跳过位于 `top:-32000px`、高度接近 0 或透明的无障碍辅助表头。
- 原字段只在“序号”右侧整体平移，不修改字段宽度。
- 只扩展 `cells`、`chcells` 和 `sz` 三个内容/滚动层，不再递归修改 FlexGrid 外层视口。
- 每行记录原始 `left` 和上次注入宽度，支持用户修改“识别内容列宽”后重新计算，避免累计偏移。

### 13.5 接口与测试补充

- 本机助手健康接口返回固定服务身份 `fanyin-local-csv-helper`。
- 本机助手保留 `/local/...` 正式路由，并兼容 `/csv/save`、`/csv/open-path` 等简写路由。
- 模型 API 收到 `/csv/save`、`/local/csv/save`、`/csv/open-path` 或 `/local/csv/open-path` 时，返回 `LOCAL_HELPER_REQUIRED`，说明接口应发往 userscript 电脑的 `127.0.0.1:18885`。
- mock `/grid` 第一行覆盖静默路径读取，第二行覆盖自动拉起详情；`/grid?helper=off` 覆盖助手未启动提示。
- performance 音频资源按 `URL + startTime` 只消费一次，脚本内部切片下载 URL 单独登记并排除，避免历史切片被绑定到后来选中的列表行。
- 普通列表和 VX 操作区使用内容指纹，仅在状态或内容变化时替换按钮 DOM，避免定时扫描打断用户点击。

## 14. 2026-06-23 命名、中文 CSV、刷新与去重补充

### 14.1 最终命名口径

- 普通语音的控制台标题、业务去重键和 CSV 文件名使用同一组字段：`案件名称+侦控号码+对方号码+通话开始时间+预估时长（秒）+index=0`。
- 底层 `targetfile` 不再参与普通语音和 VX 的业务去重，避免反复打开同一通话时生成重复任务。
- 同一任务捕获到的多个 `targetfile` 和音频 URL 会合并记录到 CSV；实际合并切片范围另写入“切片索引范围”，例如 `0-5`。
- 字段缺失时使用“未知案件”“未知侦控号码”“未知对方号码”“未知开始时间”“未知时长”等占位，不阻断识别。

### 14.2 中文 CSV

- userscript 只生成中文表头 CSV。
- 本机缓存读取只接受中文表头；旧英文 CSV 视为旧版缓存并忽略。
- 自动识别必须等待本机缓存查询完成；命中中文 CSV 时直接展示缓存，不得因异步竞态重复调用模型。
- 模型端修正接口按“分段序号”或“开始时间（毫秒）/结束时间（毫秒）”定位行，并更新“修正文本”“是否修正”“更新时间”。
- 本机助手和模型端均保留中文文件名，只替换 Windows 文件名非法字符。

### 14.3 手动识别与刷新

- Wijmo 隐藏行数据可读时继续静默构造音频 URL。
- 隐藏路径不可读时，准确定位并双击“案件名称”字段，不再点击整行的任意位置。
- 控制台音频列表增加刷新按钮：重新检测服务、扫描当前页面、执行业务去重、刷新本机 CSV 状态和顶部错误提示。
- 手动刷新发现的新音频不会自动加入识别队列，避免“刷新”产生隐式业务操作。

### 14.4 回归重点

- 第二行无隐藏音频路径时，点击“手动识别”必须触发案件名称双击并捕获音频。
- 同一行详情反复打开、每次返回不同 `targetfile` 时，控制台只保留一个业务任务。
- CSV 首行必须为中文字段，服务端修正后不得新增英文列。
- 自动识别开启且本机已有中文 CSV 时，本机文件内容保持不变，模型端不得收到该任务的重复保存。
- 刷新后任务数量稳定、服务状态和错误提示更新，且不自动开始新识别。

## 15. 2026-06-23 字段映射、等待捕获、VX 布局与说话人修复

### 15.1 普通列表字段

- 案件名称、侦控号码、对方号码、主被叫、预估时长和通话开始时间必须按 Wijmo 表头/绑定字段读取。
- DOM 读取按单元格原始 `left` 与表头位置配对，不能依赖当前 DOM 子节点下标。
- 号码字段过滤“主叫/被叫”等方向文字并优先提取实际号码。
- 时长限制在 24 小时以内；号码误入时长字段时降级为“未知时长”，不得生成“86137XXX秒”。
- 通话开始时间必须符合日期时间格式，否则降级为“未知开始时间”。

### 15.2 等待用户点开音频

- 普通列表未捕获音频时显示“等待点开音频”。
- 点击后进入 60 秒等待状态，按钮显示“等待中...”。
- 脚本不自动读取隐藏音频路径、不自动点击或双击业务列表。
- 用户自行点开语音后，下一条 `index=0` 音频流绑定到等待行并开始识别。

### 15.3 VX 操作区

- VX 的操作按钮挂载到最外层音频横向容器。
- 工具区使用 `margin-left:auto` 固定在音频和时长右侧。
- 定时扫描发现旧位置按钮时应把同一工具节点移动到新位置，避免重复按钮。

### 15.4 说话人识别

- 服务端不再对模型聚类 ID 直接加 1，而是按首次出现顺序映射为连续编号。
- userscript 对 API 返回和本地中文 CSV 再执行一次连续编号规范化，兼容未重启服务或旧缓存。
- 说话人识别只保留开关；开启后由 ModelScope 自动判断人数。

## 16. 2026-06-23 便携 Node 与 CSV另存

### 16.1 离线客户端

- 正式交付仅支持 Windows 10/11 x64。
- 离线客户端包内置 `local_helper/runtime/node.exe`，现场不安装 Node.js、不访问互联网。
- 运行时只进入离线交付包，不提交 Git。
- 启动 BAT 优先使用便携 Node，开发目录才允许回退系统 Node。
- 打包脚本记录 Node 版本、架构和 SHA-256，生成目录与 ZIP 两种交付物。

### 16.2 双按钮语义

- “CSV另存”和“打开文件路径”同时存在，不互相替代。
- “CSV另存”用于用户自主选择保存位置，不依赖本机助手。
- “打开文件路径”用于在资源管理器中选中本机助手已经落盘的 CSV。
- 本机助手不可用时，“打开文件路径”禁用，但“CSV另存”在已有转写结果时保持可用。

### 16.3 CSV 下载来源

1. 优先使用任务内存中的中文 CSV。
2. 如果任务已有分段但没有 CSV 文本，现场重新生成中文 CSV。
3. 如果内存没有结果，调用模型端 `/translator/csv` 读取最新版本。
4. 三者都不存在时显示明确错误，不生成伪空文件。

### 16.4 下载兼容

- 浏览器支持时优先调用 `showSaveFilePicker`，让用户直接选择 CSV 文件名和保存位置。
- 原生保存选择器不可用、被 userscript 隔离环境拒绝或发生兼容性错误时，退回 `<a download>` 浏览器下载。
- 回退模式不能强制弹出保存位置，由浏览器“每次下载前询问保存位置”设置决定。

## 17. 2026-06-23 CSV另存与助手状态修复

- “另存为CSV”统一改名为“CSV另存”。
- 点击后必须立即显示保存窗口或可见状态反馈，不能静默等待下载回调。
- 助手连接状态显示 userscript 实际连接的 URL 端点。
- `primary_ip` 保留为模型端 CSV `{ip}` 目录标识，但单独说明，不作为助手连接地址展示。
